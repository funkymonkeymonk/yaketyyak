# Problem

The shave workflow accepts PiConfig (model, tools, skills) only at CLI invocation
time via --pi-model/--pi-tools/--pi-skill flags. Different yaks need different agent
scopes — a docs yak needs only read, a refactor yak needs full tools plus specific
skills. Passing config on the CLI every time is error-prone and prevents autonomous
dispatch.

# Solution

Store agent config in the yak itself via `yx field <yak> agent_config` as a JSON
blob. `RunAgent` reads `yx show <yak> --format json` (already happens to get the
context), parses the `agent_config` custom field, and merges it with the
workflow-level PiConfig. Yak-embedded values win over workflow defaults for each
field that is set.

## Config shape

```json
{ "model": "...", "tools": ["read","bash","edit","write"], "skills": ["path/to/skill.md"], "maxReviewRounds": 1 }
```

- `skills`: paths relative to repo root, resolved to absolute at runtime in the worker
- `maxReviewRounds`: max adversarial review iterations (0 = disabled, default 1)
- All fields optional — missing fields fall back to workflow-level PiConfig or defaults

## Setting config on a yak

```bash
echo '{"model":"claude-sonnet-4-6","tools":["read"],"maxReviewRounds":0}' \
  | yx field "my yak" agent_config
```

# Files

- `worker/src/types.ts` — add `maxReviewRounds?: number` to `PiConfig`
- `worker/src/run-agent.ts` — add `readAgentConfig()` that parses `yx show --format json`,
  merges yak config over workflow cfg arg
- `temporal/types.go` — add `MaxReviewRounds int` to `PiConfig`

# Acceptance Criteria

- [ ] `yx field <yak> agent_config '{"model":"...","tools":[...]}'` is read and applied by RunAgent
- [ ] Yak-embedded fields override workflow-level PiConfig per field (not all-or-nothing)
- [ ] Missing or empty agent_config falls back to workflow defaults gracefully
- [ ] `maxReviewRounds` defaults to 1 if not set anywhere
- [ ] `maxReviewRounds: 0` disables adversarial review for that yak
