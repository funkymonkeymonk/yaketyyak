# Problem

`CreateDraftPR` in `worker/src/activities.ts` does a plain `git push` to the shave branch. If a branch with the same name already exists on the remote (e.g. a leftover from a previously merged or abandoned PR), the push is rejected with "fetch first", and the entire `YakWorkflow` fails.

This happened when the `shave/richer-pr-descriptions` branch was a stale leftover from PR #2 (healthcheck endpoint) — unrelated commits on the same ref caused the push to be rejected non-fast-forward.

# Acceptance Criteria

- [ ] Before pushing, `CreateDraftPR` checks whether the remote branch already exists
- [ ] If it exists, it is deleted before the push proceeds
- [ ] The push succeeds even when a stale branch with the same name is present on the remote
- [ ] `cd worker && npm run build` passes

# Files

- `worker/src/activities.ts` — `CreateDraftPR` function

# Notes

## Detection

Use the existing `run()` helper to run:

```bash
git ls-remote --heads origin <branchName>
```

If the output is non-empty, the branch exists remotely.

## Deletion

Delete via the GitHub API using octokit rather than `git push origin --delete`, to avoid needing extra git credentials setup:

```typescript
await octokit.rest.git.deleteRef({
  owner,
  repo,
  ref: `heads/${branchName}`,
});
```

Wrap in try/catch — if the delete fails (e.g. 404 race), log and continue.

## Alternative: force push

A simpler alternative is `git push --force origin <branch>`. This is acceptable since the shave branch is always agent-owned and never shared. If force push is preferred over the API delete approach, that is fine too — document the choice.
