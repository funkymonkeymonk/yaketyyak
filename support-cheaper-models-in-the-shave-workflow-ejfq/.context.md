# Problem

Pi's tool-calling format is only compatible with a subset of models. Testing
against the LiteLLM gateway showed:

- claude-sonnet-4-6 ✓
- claude-haiku-4-5-20251001 ✓
- claude-opus-4-5-20251101 ✓
- moonshotai.kimi-k2.5 ✗ (malformed_model_output)
- moonshot.kimi-k2-thinking ✗ (malformed_model_output)

`DefaultPiModel` is hardcoded to `claude-sonnet-4-6`. Simple yaks (docs
updates, config changes, renaming) don't need sonnet — haiku is cheaper and
fast enough. But there is no mechanism to select a cheaper model without
manually passing `--pi-model` every time, and no fast-fail when an
incompatible model is configured.

# Solution

Two independent improvements, implement in order:

## 1. Fast-fail on incompatible models (smaller change)

Before starting the Pi session in `RunAgent`, check if the configured model is
known-incompatible and throw a clear error immediately rather than wasting
an agent run.

Maintain a small `INCOMPATIBLE_MODELS` set in `worker/src/types.ts`:

```typescript
export const INCOMPATIBLE_MODELS = new Set([
  "moonshotai.kimi-k2.5",
  "moonshot.kimi-k2-thinking",
]);
```

In `RunAgent`, before `createAgentSession`, check and throw if the resolved
model name is in the set.

## 2. Model selection via yak agent_config (larger change, depends on pi-config yak)

Once yak-embedded agent_config is implemented (see "define pi agent
configuration" yak), the `model` field can be set per-yak. Document the
known-good model list so humans/agents know what to put there.

No automatic task-complexity-based selection for now — that requires heuristics
with no clear benefit over just setting it explicitly in the yak.

## Known-good model list (as of 2026-05-27)

| Model | Speed | Cost | Use for |
|-------|-------|------|---------|
| claude-haiku-4-5-20251001 | fast | cheap | docs, config, simple fixes |
| claude-sonnet-4-6 | medium | medium | default, general purpose |
| claude-opus-4-5-20251101 | slow | expensive | complex refactors, architecture |

# Files

- `worker/src/types.ts` — add `INCOMPATIBLE_MODELS` set
- `worker/src/run-agent.ts` — add pre-flight model check before `createAgentSession`
- `AGENTS.md` or `docs/reference/workflow-options.md` — document known-good model list

# Acceptance Criteria

- [ ] Configuring an incompatible model throws a clear error before any agent work starts
- [ ] Error message names the model and says it does not support Pi tool-calling
- [ ] `claude-haiku-4-5-20251001` is documented and usable via `--pi-model` or yak agent_config
- [ ] Known-good model list is documented in reference docs
- [ ] `INCOMPATIBLE_MODELS` list is easy to extend as new models are tested
