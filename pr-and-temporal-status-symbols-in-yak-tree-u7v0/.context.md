# Goal
Show compact inline status symbols on each yak row in the tree so users can see
PR and Temporal workflow state at a glance without opening a detail view.

Proposed layout per yak row:
  ├─ ● my yak name  [PR:●] [WF:◎]

Where symbols indicate:
  PR: ● open (green), ✓ merged (gray), ✗ closed (red), · none (dim)
  WF: ◎ running (gold), ✓ completed (gray), ✗ failed (red), · none (dim)

# Acceptance Criteria
- [ ] Yaks with a `.pr` file show a PR status symbol after the name
- [ ] Yaks with an active Temporal workflow show a WF status symbol after the name
- [ ] Symbols use distinct colors per state (open/merged/closed/running/done/failed)
- [ ] Symbols are compact — 4–6 chars max per indicator so tree doesn't overflow
- [ ] When no PR or WF exists, the symbol slot is either blank or shows a dim dot
- [ ] Terminal width is respected — symbols are truncated/hidden if row too narrow

# Notes
- PR state requires a GitHub API call (currently `PRLine.State` is always empty).
  For a first pass, showing only whether a `.pr` file exists (PR:·=none, PR:?=url-present)
  is acceptable without live API calls.
- Temporal state requires a live Temporal client query. For a first pass, showing
  the deterministic workflow ID existence is acceptable.
- This yak is intentionally scoped to the rendering layer. Live status fetching is
  a separate concern (see "temporal live polling in tui" and GitHub API integration).
