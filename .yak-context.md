# Problem

The `yyx-worker` Temporal worker process has no health endpoint. The devenv
`worker` process restarts on failure, but there is no way for external tooling
(monitoring, Docker health checks, or a future Kubernetes liveness probe) to
verify the worker is up and actually polling the Temporal task queue.

A worker can be "running" (process alive) but not healthy — for example if
the Temporal connection drops and the worker is stuck reconnecting.

# Solution

Add a minimal HTTP health server to `worker/src/worker.ts` that starts
alongside the Temporal worker. It exposes a single `GET /health` endpoint.

## Endpoint behaviour

- **200 OK** — worker is running and the Temporal worker is in a polling state
- **503 Service Unavailable** — worker process is alive but Temporal worker is
  not yet ready or has errored
- Response body: `{"status":"ok","taskQueue":"yaketyyak-tasks"}` (200) or
  `{"status":"error","reason":"..."}` (503)

## Implementation approach

Use Node's built-in `node:http` — no new dependencies. Track worker readiness
with a simple boolean flag set after `worker.run()` begins (i.e. after the
Temporal worker starts polling). The HTTP server runs in parallel on a
configurable port (default 8080, env var `HEALTH_PORT`).

```typescript
// Pseudocode
const server = http.createServer((req, res) => {
  if (req.url === "/health" && req.method === "GET") {
    res.writeHead(ready ? 200 : 503, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ status: ready ? "ok" : "error", taskQueue: TASK_QUEUE }));
  }
});
server.listen(port);

const worker = await Worker.create({ ... });
ready = true;
await worker.run();  // blocks until shutdown
```

## devenv integration

Update `devenv.nix` `worker` process to add a `readiness_probe` that hits
`GET http://localhost:8080/health` — mirrors how `temporal-dev-server` already
has a readiness probe. This lets process-compose wait for the worker to be
healthy before marking it as ready.

# Files

- `worker/src/worker.ts` — add HTTP health server using `node:http`
- `devenv.nix` — add `readiness_probe` to the `worker` process block using
  `curl -sf http://localhost:${HEALTH_PORT:-8080}/health`

# Acceptance Criteria

- [ ] `GET /health` returns 200 after worker starts polling Temporal
- [ ] `GET /health` returns 503 before the worker is ready
- [ ] Health port is configurable via `HEALTH_PORT` env var (default 8080)
- [ ] No new npm dependencies — uses `node:http` only
- [ ] `devenv.nix` worker process has a readiness_probe hitting `/health`
- [ ] Response body is valid JSON with at minimum a `status` field
