# Problem

Refining a yak from scratch is tedious and inconsistent. There is no standard
structure for yak context, making yaks harder to shave autonomously — agents
get inconsistent specs and produce inconsistent results.

# Solution

Markdown template files in `.yaks/templates/` that humans and agents copy and
fill in when creating or refining yaks.

# Templates to create

## `.yaks/templates/basic.md`

Standard shave-ready yak:

```markdown
# Problem
[What is wrong or missing, and where]

# Acceptance Criteria
- [ ] Specific, verifiable outcome
- [ ] Another verifiable outcome

# Files
- path/to/file.ts (what to change)

# Notes
[Constraints, prior art, anything the agent should know]
```

## `.yaks/templates/with-agent-config.md`

Same as basic, plus an agent_config section:

```markdown
# Problem
...

# Acceptance Criteria
- [ ] ...

# Files
- ...

# Agent Config
Store this as a yak field before shaving:
    echo '{"model":"claude-sonnet-4-6","tools":["read","bash","edit","write"],"skills":[],"maxReviewRounds":1}' \
      | yx field "<yak name>" agent_config

Minimal read-only variant (docs, reviews):
    echo '{"tools":["read"],"maxReviewRounds":0}' | yx field "<yak name>" agent_config
```

# Files
