## Goal

Add a \`yy resume <yak-name> --pr <number> --repo-url <url>\` CLI subcommand (Go, Cobra) that starts a new \`YakWorkflow\` execution with \`resumePrNumber\` set, or signals an existing workflow to resume via \`SignalWithStart\`.

## Prerequisites

- "add resume fields to WorkflowConfig and types" must be done

## Acceptance Criteria

- [ ] New file \`cmd/resume.go\` with a \`resumeCmd\` registered on \`rootCmd\`
- [ ] Usage: \`yy resume <yak-name> --pr <number> --repo-url <url>\`
- [ ] \`--pr\` flag is required; \`--repo-url\` flag is required
- [ ] \`--pi-model\`, \`--pi-tools\`, \`--pi-skill\` flags match \`shave.go\` for consistency
- [ ] Uses \`client.StartWorkflow\` with \`WorkflowIDReusePolicy = AllowDuplicate\` so it can start even if a previous run for the same yak exists
- [ ] Sets \`cfg.ResumePrNumber\` to the provided \`--pr\` value
- [ ] Prints the workflow ID and run ID on success (same format as \`shave.go\`)
- [ ] \`go build ./...\` passes

## Files

- \`cmd/resume.go\` — new file

## Notes

Workflow ID should be \`temporal.YakWorkflowID(yakName)\` (same as shave) — using \`AllowDuplicate\` reuse policy lets us launch a fresh execution under the same logical ID without conflicting with a terminated one. This is simpler than signal-with-start and sufficient for the immediate use case.
