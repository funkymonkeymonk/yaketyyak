# Goal

Implement an `IssueTriageWorkflow` Temporal workflow that triages newly-filed issues autonomously. When triggered (via signal or poll), it dispatches a sandboxed agent to attempt reproduction, gathers context if it can't reproduce, and posts a comment back on the issue with findings. A yak is created only when the issue is confirmed valid/reproducible.

The workflow is issue-board agnostic: all issue operations go through a thin `IssueProvider` interface so GitHub can be swapped for Linear or Jira without touching the workflow.

## Acceptance Criteria

- [ ] `IssueProvider` interface defined with at minimum: `getIssue`, `postComment`, `labelIssue`
- [ ] `Issue` normalized type defined (id, title, body, url, labels, author)
- [ ] `IssueTriageWorkflow` implemented in `worker/src/workflow.ts` (or a new file)
- [ ] Workflow accepts a signal carrying a normalized `Issue` as input
- [ ] Workflow dispatches a sandboxed Pi agent activity with read-only repo access and no secrets
- [ ] Agent is given sanitized issue content (prompt injection threat model documented)
- [ ] Agent attempts to reproduce; falls back to context-gathering if it cannot
- [ ] Workflow posts a freeform comment via `IssueProvider.postComment` with findings
- [ ] Yak is created (via `yx add` + `yx context`) only when issue is confirmed valid
- [ ] GitHub implementation of `IssueProvider` exists (`worker/src/providers/github.ts`)
- [ ] Polling trigger support: a separate activity that polls for newly-labelled issues and fires the signal
- [ ] Webhook trigger support: a signal endpoint that can be called directly (e.g. from a GitHub webhook handler)
- [ ] Both trigger paths use the same normalized `Issue` input — provider does the translation

## Out of Scope

- Issue input template (separate yak)
- Linear / Jira provider implementations (future)
- Pushing commits or creating PRs from the triage agent

## Files

- `worker/src/workflows/issueTriage.ts` — new workflow
- `worker/src/providers/issueProvider.ts` — interface + normalized types
- `worker/src/providers/github.ts` — GitHub implementation
- `worker/src/activities/triage.ts` — triage-specific activities (dispatch agent, create yak)
- `worker/src/types.ts` — extend with `Issue`, `IssueTriageInput`
- `worker/src/worker.ts` — register new workflow + activities

## Security Notes

- Issue title and body must be passed to the agent as data, not interpolated into the system prompt
- Agent tool allowlist: read-only filesystem, `go build`, `devenv tasks run` — no git push, no network calls outside the repo
- No secrets (GITHUB_TOKEN, LITELLM_API_KEY, etc.) in the agent's environment
