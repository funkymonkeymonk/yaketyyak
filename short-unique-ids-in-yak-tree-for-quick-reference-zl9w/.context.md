# Goal
Display a short unique ID prefix before each yak name in the tree so users can
reference yaks with minimal keystrokes (e.g. for future command-palette or
jump-to-yak features).

`yx` already assigns a slug ID to each yak stored in `.yaks/<path>/.id`. The last
4–5 chars of that slug (the random suffix) are already unique within a repo.
Example: `yak-detail-popup-overlay-in-tui-hnar` → short ID `hnar`.

Proposed tree layout:
  ├─ hnar ● yak detail popup overlay in tui
  ├─ u7v0 ○ pr and temporal status symbols in yak tree

# Acceptance Criteria
- [ ] Each yak row shows a short ID prefix (4–5 chars) before the yak name
- [ ] Short ID is visually distinct from the name (dim color, monospace)
- [ ] Short IDs are unique within the visible tree
- [ ] Extraction logic: take the last hyphen-delimited segment of `.id` file content
- [ ] Short ID column is fixed-width so names align across rows
- [ ] If `.id` is absent or has no hyphen suffix, fall back to first 4 chars of path hash

# Files
- tui/yaks.go (extract short ID from YakLine.ID during load)
- tui/types.go (add ShortID string field to YakLine)
- tui/render.go (renderTreeLine — prepend short ID with fixed-width dim style)

# Notes
- The short ID `hnar` for `yak-detail-popup-overlay-in-tui-hnar` is already
  visible in `yx ls` output implicitly. We're just surfacing it in the TUI.
- Repo rows should not show a short ID (they have no `.id` file).
