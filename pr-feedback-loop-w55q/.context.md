# Goal

When a PR reviewer submits a `REQUEST_CHANGES` review on a yak's PR, the workflow should detect it via polling, re-dispatch the coding agent with the full context (original yak spec + review comments + current diff), push a new commit addressing the feedback, reply to the review on the PR, and return to `waiting-for-merge`. This loops indefinitely until the PR is merged, closed, or a `wont-do` signal is received.

**No webhooks. No new CLI commands. No extra infrastructure.**
Trigger: GitHub `REQUEST_CHANGES` review (standard GitHub review UI).
Detection: polling inside the existing activity layer.

# Architecture

## New types in `worker/src/types.ts`

Add `PRWatchOutcome`, `PRWatchResult`, `ReviewComment` types.
Add `feedbackRound: number` to `YakWorkflowState` (0 = initial implementation).

## Changes to `worker/src/activities.ts`

1. Rename `WatchPRMerged` → `WatchPRState(prNumber, repoUrl, lastReviewId)` returning `PRWatchResult`
   - Same 60s poll + heartbeat
   - Also polls `listReviews` for CHANGES_REQUESTED reviews with reviewId > lastReviewId
   - Fetches comments via `listCommentsForReview` and returns `{ outcome: "feedback", ... }`

2. New `RespondToReview(repoUrl, prNumber, reviewId, message)` — posts PR comment via `issues.createComment`

3. New `PushFeedbackCommit(repoUrl, workspaceName, round)` — `git add -A && git commit && git push`

## Changes to `worker/src/workflow.ts`

Replace one-shot wait with a loop:
  - Check wontDo at top of each iteration
  - Call WatchPRState; on "feedback" → addressing-feedback phase → RunAgent with feedbackContext → PushFeedbackCommit → RespondToReview → update lastReviewId → loop
  - On "merged" → done; on "closed" → release

## Changes to `worker/src/run-agent.ts`

Add optional `feedbackContext?: string` to `RunAgent`.
Append formatted review body + per-line comments to Pi context when provided.
Agent receives: full yak spec + feedback block.

# Acceptance Criteria

- [ ] WatchPRState returns feedback outcome for REQUEST_CHANGES reviews with reviewId > lastReviewId
- [ ] Workflow enters addressing-feedback phase and re-dispatches agent
- [ ] Agent receives full yak spec + formatted review comments
- [ ] New commit pushed to same branch/PR after agent completes
- [ ] PR comment posted summarising changes made
- [ ] lastReviewId updated so same review does not re-trigger
- [ ] Loop repeats on subsequent REQUEST_CHANGES reviews
- [ ] wont-do signal works at any point in the loop
- [ ] feedbackRound reflected in yak_status query
