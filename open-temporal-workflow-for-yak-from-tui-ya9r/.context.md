# Goal
Allow the user to open the Temporal UI for the workflow associated with a yak
directly from the TUI using a key binding (e.g. `t`). Uses the deterministic
workflow ID (`temporal.YakWorkflowID(yak.Name)`) to construct a Temporal UI URL
and opens it in the system browser.

# Acceptance Criteria
- [ ] Pressing `t` on a yak opens the Temporal UI URL for that yak's workflow in the browser
- [ ] Temporal UI base URL is configurable (default: `http://localhost:8080`)
- [ ] Constructed URL format: `<base>/namespaces/default/workflows/<workflowID>`
- [ ] If no Temporal UI URL is configured, show status "configure --temporal-ui-url to use this"
- [ ] The browser open is non-blocking (fire-and-forget)
- [ ] Key hint `t:workflow` is shown in the help bar

# Files
- tui/keys.go (add OpenWorkflow key binding)
- tui/model.go (handle OpenWorkflow — construct URL, run open/xdg-open)
- tui/context.go or cmd/tui.go (add --temporal-ui-url flag, thread into Model)
- tui/footer.go (add hint to help text)

# Notes
- `temporal.YakWorkflowID(name)` already exists in `temporal/types.go:34`.
- `Repo.WFID` holds the orchestrator workflow ID — `t` on a repo row could open
  the orchestrator workflow instead.
- The Temporal UI URL base can be stored on `ProgramContext` alongside `llmConfig`.
- Same `open`/`xdg-open` pattern as "open github pr for yak from tui".

## Prerequisites
- open github pr for yak from tui (establishes the browser-open pattern)
