# Shave Workflow (YakWorkflow)

## Purpose

A single long-running Temporal workflow per yak. Starts when a yak is marked
`@g2g`, ends only when the yak is closed (merged or won't-do).

## Lifecycle

```
@g2g tagged
     │
     ▼
yx start <yak>              ← lock: state = wip
     │
     ▼
coding agent implements     ← subprocess: opencode/claude/pi with spec from .context.md
     │
     ▼
gh pr create --draft        ← PR opened in draft state
     │
[WAIT] human converts to ready-for-review
     │
[WAIT] required approvals met
     │
     ▼
human merges (or auto-merge on approval)
     │
[WAIT] PR merged event      ← workflow polls gh pr view until merged
     │
     ▼
yx done <yak>               ← unlock, close
workflow ends

── at any point ──
signal: wont-do → yx done <yak> → workflow ends
```

## Key design decisions

- **One workflow per yak**, ID = yak ID. No shared orchestrator doing implementation.
- **Yaks as lock**: `wip` state means this workflow owns the yak. Nothing else touches it.
- **Yaks as state store**: `.context.md` = spec, `.pr` = PR URL. Temporal holds in-flight state.
- **Agent subprocess, not raw LLM**: coding agent (opencode, claude, etc.) handles
  its own tool-calling loop. The workflow treats the agent run as a single activity.
- **Workflow does NOT merge**: it waits for a human merge event. `gh pr merge --auto`
  can be set as a flag on the PR, but the workflow observes, doesn't drive.
- **CI failures resume the agent**: if CI fails after PR is open, the workflow
  signals the agent to fix it. The agent pushes a new commit; CI reruns.

## Signals

| Signal | Effect |
|--------|--------|
| `wont-do` | Skip merge wait, close yak, end workflow |
| `ci-failed` | Wake agent to fix CI failures (if not already watching) |
| `pr-feedback` | Pass review comments to agent for addressing |

## Activities

1. `ClaimYak` — `yx start <yak>`
2. `RunAgent` — subprocess coding agent, spec from `.context.md`, workspace = jj workspace
3. `CreateDraftPR` — `gh pr create --draft`
4. `WatchPRMerged` — poll `gh pr view --json state,merged` until merged or won't-do signal
5. `CloseYak` — `yx done <yak>`

## Out of scope

- Barber/refinement logic
- Dependency management between yaks
- Spawning multiple YakWorkflows (that's the Barber's job if needed)
