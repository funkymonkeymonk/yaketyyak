# Problem

An agent that implements its own work has anchoring bias — it verifies that its
solution executes, not that it satisfies the original spec. A fresh reviewer
with no knowledge of the implementation catches spec drift, missing acceptance
criteria, and regressions that the implementer missed.

# Solution

Add a review phase to `YakWorkflow` immediately after `RunAgent`. A separate Pi
session runs with read-only tools and a reviewer system prompt. It sees the
original yak spec and the workspace diff, then verdicts PASS or FAIL with
specific reasons tied to the acceptance criteria.

On FAIL, the implementer runs again with the review feedback appended to its
context. The loop repeats up to `maxReviewRounds` times. On PASS or exhaustion
the workflow proceeds to PR creation.

This is a ralph loop — the same agent type (Pi) runs repeatedly until it passes
its own adversarial review or hits the round limit.

## Reviewer configuration

- **tools**: `["read"]` only — no bash, no edit, no write
- **model**: same model as implementer (from PiConfig)
- **sessionManager**: `SessionManager.inMemory()` — no session state persisted
- **system prompt**: "You are an adversarial code reviewer. You did not write
  this code. You have the original spec and the diff of changes made. Your job
  is to verify every acceptance criterion is met. Verdict: PASS or FAIL. On
  FAIL, list each unmet criterion with specific evidence from the diff."
- **context**: yak spec (`.yak-context.md`) + output of `jj diff` in workspace

## Review result shape

```typescript
interface ReviewResult {
  verdict: "PASS" | "FAIL";
  reasons: string[]; // empty on PASS, specific on FAIL
}
```

## Workflow phase changes

```
implementing
    │
    ▼
reviewing  ← new phase (visible in YakWorkflowState.phase)
    │
    ├─ PASS → creating-pr
    │
    └─ FAIL + attempts remaining → implementing (with feedback appended)
             + attempts exhausted → creating-pr with warning in PR body
```

## maxReviewRounds

- Sourced from `PiConfig.maxReviewRounds` (set via yak agent_config field or CLI)
- Default: 1
- 0 = review phase skipped entirely

# Files

- `worker/src/run-agent.ts` — add `runReviewer()`, add review loop in `RunAgent`
- `worker/src/types.ts` — add `ReviewResult`, add `maxReviewRounds` to `PiConfig`
- `temporal/types.go` — add `MaxReviewRounds int` to `PiConfig` (coordinate with pi config yak)
- `temporal/workflow.go` — expose "reviewing" as a valid phase in `YakWorkflowState`

# Acceptance Criteria

- [ ] Reviewer runs after each agent implementation pass
- [ ] Reviewer uses `tools: ["read"]` only — no bash, edit, or write
- [ ] PASS verdict proceeds to `creating-pr`
- [ ] FAIL verdict re-runs implementer with review feedback appended to context (up to maxReviewRounds)
- [ ] `maxReviewRounds: 0` skips the review phase entirely for that yak
- [ ] `phase: "reviewing"` is visible in `YakWorkflowState` during review
- [ ] On exhaustion (all rounds FAIL), workflow proceeds to PR with a note in the PR body
