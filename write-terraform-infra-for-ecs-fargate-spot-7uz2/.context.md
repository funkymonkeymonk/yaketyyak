# Problem
No AWS infrastructure exists for running the yyx worker. We need ECS Fargate
Spot task definitions, an ECR repo, SSM parameters for secrets, IAM roles, and
a security group — all in Terraform with local state for now.

# Acceptance Criteria
- [ ] `infra/` directory created with the following files:
  - `providers.tf` — AWS ~5.0 provider; no backend block (local state)
  - `variables.tf` — `region`, `vpc_id`, `private_subnet_ids` (list), `image_tag`, `app_name` (default "yyx")
  - `ecr.tf` — `aws_ecr_repository "yyx-worker"` with `image_tag_mutability = "MUTABLE"` and a lifecycle policy keeping the last 10 images
  - `iam.tf` — ECS task execution role with `AmazonECSTaskExecutionRolePolicy` + inline SSM read policy; minimal task role (no AWS API calls from task)
  - `secrets.tf` — `aws_ssm_parameter` for: `/yyx/temporal_host_port` (placeholder "REPLACE_ME"), `/yyx/litellm_api_key` (SecureString, sensitive), `/yyx/litellm_base_url`, `/yyx/github_token` (SecureString, sensitive)
  - `ecs.tf` — ECS cluster + 2 task definitions + 2 services:
    - `shaver`: 4 vCPU / 8 GB, `FARGATE_SPOT` capacity provider (weight 1, base 0), `desired_count = 0`, `WORKER_ROLE=shaver`, all 4 SSM params as secrets
    - `watcher`: 0.25 vCPU / 0.5 GB, `FARGATE_SPOT` (weight 1, base 0), `desired_count = 0`, `WORKER_ROLE=watcher`, only `temporal_host_port` + `github_token` as secrets
  - `network.tf` — `aws_security_group "yyx-worker"`: no ingress, egress port 443 to `0.0.0.0/0` (GitHub API, Temporal, LiteLLM)
  - `outputs.tf` — `ecr_repo_url`, `cluster_arn`, `shaver_service_arn`, `watcher_service_arn`
- [ ] Both services use `launch_type = null` and `capacity_provider_strategy` (not deprecated `launch_type = "FARGATE"`)
- [ ] Both services deployed to `private_subnet_ids` with `assign_public_ip = false`
- [ ] Both services use the `yyx-worker` security group
- [ ] Task definitions reference the ECR image as `${aws_ecr_repository.yyx_worker.repository_url}:${var.image_tag}`
- [ ] `terraform validate` passes

# Notes
Fargate task sizes: 4 vCPU requires memory between 8 GB and 30 GB; 0.25 vCPU
supports 0.5 GB. Use `cpu = 4096` / `memory = 8192` for shaver and
`cpu = 256` / `memory = 512` for watcher in the task definition resource.
Both services start at desired_count=0 — manual or scripted scale-up for now.
KEDA integration is a separate future task.
SSM SecureString params must be referenced in task definition `secrets` blocks
(not `environment`) so ECS resolves them at launch time.
Terraform backend is local state — no `backend` block, just the `terraform {}`
required_providers block.
