# Problem
No CI/CD pipeline exists to build and push the worker Docker image to ECR or
to trigger ECS redeployments. Every push to main touching worker code should
produce a new image and force-redeploy both ECS services.

# Acceptance Criteria
- [ ] `.github/workflows/deploy-worker.yml` created
- [ ] Triggers on push to `main` with path filter: `worker/**`
- [ ] Uses OIDC AWS authentication (no long-lived `AWS_ACCESS_KEY_ID` secrets)
  - IAM role ARN read from `AWS_DEPLOY_ROLE_ARN` repository secret
  - Region read from `AWS_REGION` repository secret (or hardcoded if single-region)
- [ ] Builds `linux/amd64` image using `docker buildx`
- [ ] Logs into ECR using `aws ecr get-login-password`
- [ ] Tags image with both `${{ github.sha }}` and `latest`
- [ ] Pushes both tags to ECR
- [ ] Runs `aws ecs update-service --force-new-deployment` for both `yyx-shaver` and `yyx-watcher` services
- [ ] `image_tag` passed to ECS update matches the SHA-tagged image

## Prerequisites
- write terraform infra for ECS Fargate Spot must be done
- write worker Dockerfile must be done

# Files
- .github/workflows/deploy-worker.yml (new)

# Notes
The OIDC trust policy on the IAM role (set up outside Terraform for now — can
be added later) must allow `token.actions.githubusercontent.com` as the
federated principal with condition on the repo.
Infra changes (terraform apply) are manual — CI only handles image builds and
ECS service updates. Terraform apply gets its own task later.
Use `aws-actions/configure-aws-credentials@v4` for OIDC.
Use `aws-actions/amazon-ecr-login@v2` for ECR login.
