## Goal

Modify \`YakWorkflow\` in \`worker/src/workflow.ts\` so that when \`cfg.resumePrNumber > 0\` it skips the claim/workspace/agent/create-PR steps and jumps straight into the feedback loop with the provided PR number.

## Prerequisites

- "add resume fields to WorkflowConfig and types" must be done
- "add InitWorkspaceForResume activity" must be done

## Acceptance Criteria

- [ ] When \`cfg.resumePrNumber\` is set and > 0, workflow enters phase \`"resuming"\` then immediately \`"waiting-for-merge"\`
- [ ] It calls \`InitWorkspaceForResume\` (not \`InitWorkspace\`) to set up the workspace
- [ ] It does NOT call \`YakClaim\`, \`RunAgent\`, or \`CreateDraftPR\`
- [ ] \`state.prNumber\` and \`state.prUrl\` are set from \`cfg.resumePrNumber\` and constructed from repo URL + PR number
- [ ] The feedback loop (\`WatchPRState\`, \`RunAgent\` for feedback, \`PushFeedbackCommit\`, \`RespondToReview\`) works identically to the normal path
- [ ] \`wontDo\` signal still works in the resume path
- [ ] \`npm run build\` passes

## Files

- \`worker/src/workflow.ts\` — add resume branch at the top of \`YakWorkflow\`

## Notes

Use a simple \`if (cfg.resumePrNumber && cfg.resumePrNumber > 0)\` guard. The PR URL can be constructed as \`\`https://github.com/<owner>/<repo>/pull/<number>\`\` using the existing \`parseRepoUrl\` helper.
