# Problem

`CreateDraftPR` in `worker/src/activities.ts` creates PRs with a minimal hardcoded body:

```
Automated shave by [yaketyyak](https://github.com/funkymonkeymonk/yaketyyak)

Yak: `<yakName>`
```

Reviewers have no context about what the PR is meant to accomplish. The yak's full `.context.md` (problem, acceptance criteria, files, notes) is available via `yx show <yakName> --format json` but is never included.

The base branch is also hardcoded to `"main"` which breaks stacked-ticket workflows where a feature branch is the merge target.

# Acceptance Criteria

- [ ] PR body includes the full `.context.md` content under a `## Yak Context` heading
- [ ] PR body retains the yaketyyak attribution line at the top
- [ ] Base branch is detected from the workspace clone rather than hardcoded to `"main"`
- [ ] `cd worker && npm run build` passes

# Files

- `worker/src/activities.ts` — `CreateDraftPR` function

# Notes

## Fetching yak context

Call `yx show <yakName> --format json` inside `CreateDraftPR`, parse `data.context`. The same pattern is in `run-agent.ts:writeContextFile` (lines 192–207) — copy that approach. No need to throw if context is missing; fall back gracefully to the minimal body.

## Detecting base branch

After `git clone --depth 1` the workspace tracks `origin/HEAD`. Detect with:

```bash
git rev-parse --abbrev-ref origin/HEAD
# returns e.g. "origin/main" — strip the "origin/" prefix
```

Run this inside `CreateDraftPR` using the existing `run()` helper. Pass the result as the `base` field to `octokit.rest.pulls.create` instead of the hardcoded `"main"`.

## PR body format

```markdown
> Automated shave by [yaketyyak](https://github.com/funkymonkeymonk/yaketyyak)

## Yak Context

<verbatim .context.md contents>
```

## Extract shared helper

Extract a `detectBaseBranch(workspacePath: string): string` helper in `activities.ts`. It will be reused by the `post-implementation-pr-summary` yak.
