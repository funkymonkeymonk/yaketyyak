# Goal

Add a new step to `YakWorkflow` (in `worker/src/workflow.ts`) that runs *before*
the agent is dispatched. The step uses an LLM call to review the yak's context
against the current state of the codebase and decides whether the work still
makes sense, is already done, or has become irrelevant.

If the check determines the yak is no longer relevant, the workflow marks it
`@needs-human` with a brief explanation and exits early (without consuming an
agent run). If it looks good, the workflow proceeds normally.

## Why

Agent runs are expensive (up to 2h). A yak added weeks ago may already be
implemented, superseded by other work, or contradict the current architecture.
A cheap LLM check upfront prevents wasted agent cycles.

## New phase name

`validating`  (inserted between `claiming` and `init-workspace`)

## New activity: `ValidateYakRelevance`

**Signature:**
```ts
export async function ValidateYakRelevance(
  yakName: string,
  repoUrl: string,
): Promise<{ relevant: boolean; reason: string }>
```

**What it does:**

1. `yx show --format json <yakName>` — read yak context (title, body, tags, etc.)
2. Do a shallow clone of the repo (same pattern as `InitWorkspace` but `--depth 1`)
   — or, if a workspace already exists for this yak, read from it. Keep it
   simple: always do a fresh shallow clone into a temp dir, clean it up after.
3. Gather codebase signals to give the LLM enough to reason about:
   - Directory tree (find . -not -path '*/node_modules/*' -not -path '*/.git/*' -not -path '*/.devenv/*' -not -path '*/.workspaces/*' -maxdepth 3 -type f)
   - `git log --oneline -20`  (recent commit subjects)
   - The full yak context markdown
4. Call an LLM (use the same `LITELLM_BASE_URL` + `LITELLM_API_KEY` the worker
   already has, model: `openai/gpt-4.1-mini` or whatever cheap model is
   appropriate — make it configurable via `cfg.pi.model` falling back to a
   cheaper default like `"openai/gpt-4.1-mini"`).
5. System prompt: You are a senior engineer reviewing whether a backlog task is still worth doing. Respond ONLY with a JSON object {"relevant": true|false, "reason": "<one sentence>"}. Be conservative — only mark irrelevant if you are highly confident the task is already done or clearly no longer needed.
6. Parse the JSON response; default to `{ relevant: true, reason: "" }` on any
   parse failure (fail open so we do not drop valid work).
7. Clean up the temp clone.

**On `relevant: false`:**
- `yx tag add <yakName> @needs-human`
- Append section to yak context:  `## Pre-shave check (skipped)\n<reason>`
- `yx state <yakName> todo`  (release the claim)
- Workflow returns early with message `"yak <name> skipped: <reason>"`

**On `relevant: true`:** proceed to `init-workspace` as normal.

## Timeout and retry

```ts
const { ValidateYakRelevance } = proxyActivities<typeof allActivities>({
  startToCloseTimeout: "5 minutes",
  retry: { maximumAttempts: 2 },
});
```

## Workflow changes (worker/src/workflow.ts)

After `YakClaim`, before `InitWorkspace`:

```ts
// 1.5. Validate yak relevance before committing to a full agent run.
setPhase("validating");
const validation = await ValidateYakRelevance(yakName, cfg.repoUrl);
if (!validation.relevant) {
  return `yak ${yakName} skipped (no longer relevant): ${validation.reason}`;
}
```

## Configuration

The validation LLM model should be separate from `cfg.pi.model` (the expensive
model used for the full agent run). Add an optional `validationModel?: string`
field to `PiConfig` (both `worker/src/types.ts` and `temporal/types.go`).
Default to `"openai/gpt-4.1-mini"` when not set.
