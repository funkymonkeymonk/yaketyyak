# Problem

After the coding agent finishes and a PR is opened, reviewers have to read the diff cold. There is no explanation of what was implemented or what key technical decisions were made.

We want to post a PR comment (not edit the PR description) after the agent completes containing a short LLM-generated summary of the implementation and any notable decisions.

## Prerequisites
- richer pr descriptions must be done

# Architecture

## New activity: `PostImplementationSummary`

Add to `worker/src/activities.ts`:

```typescript
export async function PostImplementationSummary(
  yakName: string,
  workspaceName: string,
  prNumber: number,
  repoUrl: string,
  summaryModel: string,
): Promise<void>
```

Steps inside the activity:
1. Detect base branch using the shared `detectBaseBranch(workspacePath)` helper (from `richer-pr-descriptions` yak)
2. Run `git log --oneline <baseBranch>..HEAD` in workspace
3. Run `git diff <baseBranch>...HEAD` in workspace — truncate to ~8000 chars if needed, append `\n\n[diff truncated]`
4. Read yak context: `yx show <yakName> --format json`, extract `data.context`
5. Call LiteLLM via `fetch` against `${LITELLM_BASE_URL}/chat/completions` with `Authorization: Bearer ${LITELLM_API_KEY}`
6. Post the response as a PR comment via `octokit.rest.issues.createComment`

Wrap the entire body in try/catch — log errors but do not rethrow. A missing summary must never block the workflow.

## LLM prompt

```
You are summarizing a code change for a GitHub PR comment.

## Yak spec
<context>

## Commits
<git log output>

## Diff
<git diff output>

Write 2–4 sentences describing what was implemented and any notable technical decisions. Be concise and factual. Do not use bullet points.
```

## New field: `summaryModel` on `WorkflowConfig`

In `worker/src/types.ts`:
```typescript
export interface WorkflowConfig {
  repoUrl: string;
  pi: PiConfig;
  summaryModel?: string;  // defaults to DEFAULT_SUMMARY_MODEL
}
export const DEFAULT_SUMMARY_MODEL = "claude-haiku-4-5-20251001";
```

## Workflow wiring

In `worker/src/workflow.ts`, add a proxy for `PostImplementationSummary`:

```typescript
const { PostImplementationSummary } = proxyActivities<typeof allActivities>({
  startToCloseTimeout: "3 minutes",
  retry: { maximumAttempts: 2 },
});
```

Call it after `CreateDraftPR` returns and before `waiting-for-merge`, while the workspace is still alive:

```typescript
// After CreateDraftPR...
await PostImplementationSummary(
  yakName,
  state.workspace,
  pr.prNumber,
  cfg.repoUrl,
  cfg.summaryModel ?? DEFAULT_SUMMARY_MODEL,
);
```

# Acceptance Criteria

- [ ] After agent run completes, a PR comment is posted with a 2–4 sentence implementation summary
- [ ] Summary is generated via LiteLLM using `summaryModel` (default: `claude-haiku-4-5-20251001`)
- [ ] Diff covers full branch vs. auto-detected base branch (not hardcoded `"main"`, not just last commit)
- [ ] `summaryModel` is configurable on `WorkflowConfig` with `DEFAULT_SUMMARY_MODEL` exported constant
- [ ] Activity is non-fatal: LLM or GitHub API failures are caught, logged, and do not throw
- [ ] `cd worker && npm run build` passes

# Files

- `worker/src/types.ts` — add `summaryModel?: string` to `WorkflowConfig`, add `DEFAULT_SUMMARY_MODEL`
- `worker/src/activities.ts` — add `PostImplementationSummary` activity; reuse `detectBaseBranch` helper from `richer-pr-descriptions`
- `worker/src/workflow.ts` — proxy `PostImplementationSummary`, call after `CreateDraftPR`

# Notes

**Depends on:** `richer-pr-descriptions` must be done first — it introduces the `detectBaseBranch(workspacePath)` helper that this yak reuses.

**The feedback loop yak** (`pr-feedback-loop`) will call this same activity again after each feedback round. No changes needed to this activity for that — `workflow.ts` just calls it again in the feedback loop.

**LiteLLM call:** Use `fetch` directly (no Pi SDK). Model should be cheap by default (`claude-haiku-4-5-20251001`). Use the same env vars the rest of the worker uses: `LITELLM_BASE_URL` and `LITELLM_API_KEY`.

**Diff truncation:** If `git diff` output exceeds 8000 chars, slice and append `\n\n[diff truncated]`.
