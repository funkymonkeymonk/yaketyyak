# Problem
All `yx` calls in activities.ts inherit `process.cwd()` as their working
directory, which happens to be the yaketyyak repo in local dev. In the deployed
container there is no yaketyyak checkout — `yx` needs to run inside the target
repo being shaved (where `.yaks/` and `refs/notes/yaks` live). A dedicated
clone of the target repo must be created before any `yx` activity runs and
cleaned up at the end of the workflow.

# Acceptance Criteria
- [ ] `CloneYakStateRepo(repoUrl: string): Promise<string>` activity added to `activities.ts`
  - Does a full clone (not `--depth 1`) so git notes history is preserved
  - Uses authenticated URL (same `GITHUB_TOKEN` pattern as `InitWorkspace`)
  - Returns an absolute path to the cloned directory
  - Clones into an isolated temp dir (e.g. `/tmp/yak-state-<slug>-<random>`)
- [ ] `CleanupYakStateRepo(yakStatePath: string): Promise<void>` activity added
  - `rm -rf` the path returned by `CloneYakStateRepo`
- [ ] All existing `yx` call sites in activities.ts accept a `yakStatePath: string` parameter and pass it as `cwd` to `run()`
  - `YakClaim(yakName, yakStatePath)`
  - `YakRelease(yakName, reason, yakStatePath)`
  - `YakMarkDone(yakName, yakStatePath)`
  - `WritePRToYak(yakName, prUrl, yakStatePath)`
  - `fetchYakContext(yakName, yakStatePath)` (private helper)
  - `ScanG2GYaks(yakStatePath)` — repoUrl handled by caller via CloneYakStateRepo
- [ ] `yx sync` calls inside each activity use the same `cwd`

# Files
- worker/src/activities.ts (new activities + add yakStatePath param to existing yx activities)

# Notes
The clone must be full (not shallow) because `yx` reads and writes `refs/notes/yaks`
which is a git notes ref that may not be present in a shallow clone.
Use `os.tmpdir()` from `node:os` for the temp root.
Use a random suffix (e.g. `Math.random().toString(36).slice(2)`) to avoid collisions
between concurrent workflow runs shaving the same repo.
This yak does NOT update the workflow code — that is handled by
"thread yakStatePath through YakWorkflow and G2GScanWorkflow".
