# Problem
A single Docker image serves both the shaver (heavy, 4 vCPU/8 GB) and watcher
(lightweight, 0.25 vCPU/0.5 GB) ECS task definitions. The entrypoint must
branch on a `WORKER_ROLE` env var to register the correct activities and poll
the correct task queue.

# Acceptance Criteria
- [ ] `worker/src/worker.ts` reads `WORKER_ROLE` env var (default: `"shaver"`)
- [ ] When `WORKER_ROLE=shaver`:
  - Polls `TASK_QUEUE` ("yaketyyak-tasks")
  - Registers all activities (existing behaviour)
  - `maxConcurrentWorkflowTaskExecutions: 1` (one yak per task for cost attribution)
- [ ] When `WORKER_ROLE=watcher`:
  - Polls `WATCHER_TASK_QUEUE` ("yaketyyak-watcher-tasks")
  - Registers only `WatchPRMerged` activity
  - `maxConcurrentWorkflowTaskExecutions: 10` (cheap poller, can watch many PRs)
- [ ] `TEMPORAL_HOST_PORT` env var is read and used to construct an explicit `NativeConnection` when set; falls back to Temporal's default (localhost) when unset
- [ ] Startup log includes role and task queue being polled
- [ ] Unknown `WORKER_ROLE` value throws an error on startup

## Prerequisites
- externalize temporal host port config must be done
- split activities across shaver and watcher task queues must be done
- thread yakStatePath through YakWorkflow and G2GScanWorkflow must be done

# Files
- worker/src/worker.ts (WORKER_ROLE branch + NativeConnection)

# Notes
`NativeConnection` is imported from `@temporalio/worker`.
The shaver sets `maxConcurrentWorkflowTaskExecutions: 1` (was 5 previously) so
that each ECS task handles exactly one active workflow — clean cost attribution
per yak via ECS task tags.
