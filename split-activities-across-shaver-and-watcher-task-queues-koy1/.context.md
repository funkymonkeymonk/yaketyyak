# Problem
`WatchPRMerged` can run for days or weeks polling GitHub. Running it on the
same large Fargate task as `RunAgent` wastes significant money. It should be
routed to a dedicated lightweight watcher worker on its own task queue.

# Acceptance Criteria
- [ ] `WATCHER_TASK_QUEUE = "yaketyyak-watcher-tasks"` constant added to `worker/src/types.ts`
- [ ] `worker/src/workflow.ts` has a separate `proxyActivities` call for `WatchPRMerged` that specifies `taskQueue: WATCHER_TASK_QUEUE`
  - `startToCloseTimeout: "168 hours"` and `heartbeatTimeout: "2 minutes"` unchanged
- [ ] All other activities remain on the existing `TASK_QUEUE`
- [ ] No changes to the `WatchPRMerged` activity implementation itself

## Prerequisites
- externalize temporal host port config must be done (StartYakWorkflow needs the fixed address before this is wired up)

# Files
- worker/src/types.ts (add WATCHER_TASK_QUEUE constant)
- worker/src/workflow.ts (separate proxyActivities for WatchPRMerged)

# Notes
The watcher task definition will run a worker that polls WATCHER_TASK_QUEUE only.
The shaver task definition polls TASK_QUEUE and handles everything except WatchPRMerged.
Both task definitions use the same Docker image — role is set via WORKER_ROLE env var.
