# Problem

Agentic work sessions have no defined start or end ritual. This leads to
unbounded scope creep, lost context between sessions, and yak state that
drifts out of sync with what was actually done.

# Solution

A lightweight two-phase protocol for every work session, codified in AGENTS.md
and optionally as an OpenCode skill. Simple enough that both humans and agents
follow it without deviation.

## Triage (session start, ~5 min)

1. `yx sync` — pull latest state from remote
2. `yx ls` — survey the full map
3. Set a hard stop time before starting (e.g. "done by 17:00")
4. Pick at most 2 yaks to work on (WIP limit); note them explicitly
5. Flag any `@needs-human` yaks to surface to the human before diving in

## Wrap (session end)

1. `yx sync` — push any state changes made during the session
2. Update context on any in-progress yaks with a progress note:
   `echo "Did X, Y. Blocked on Z." | yx context "<yak>"`
3. Prune noise if the map is cluttered: `yx ls --all` then `yx prune`
4. Leave a one-line handoff note in any wip yak's context for the next session

## WIP limit rationale

Two yaks maximum per session. More than two means context-switching overhead
exceeds value delivered. If a yak blocks, note it and move to the other one —
don't open a third.
