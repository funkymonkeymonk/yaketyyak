# Problem
`YakWorkflow` and `G2GScanWorkflow` call `yx`-backed activities without
providing a working directory. Now that `CloneYakStateRepo` and
`CleanupYakStateRepo` exist, both workflows must clone the target repo for yak
state management, thread the path through to all `yx` activities, and clean up
on completion or error.

# Acceptance Criteria
- [ ] `YakWorkflowState` has a `yakStatePath: string` field
- [ ] `YakWorkflow` calls `CloneYakStateRepo(cfg.repoUrl)` as the very first step (before `YakClaim`)
- [ ] `state.yakStatePath` is populated with the result
- [ ] All `yx`-using activity calls in `YakWorkflow` pass `state.yakStatePath`:
  - `YakClaim(yakName, yakStatePath)`
  - `YakRelease(yakName, reason, yakStatePath)`
  - `YakMarkDone(yakName, yakStatePath)`
  - `WritePRToYak(yakName, prUrl, yakStatePath)`
- [ ] `CleanupYakStateRepo(state.yakStatePath)` is called in the `finally` block alongside `CleanupWorkspace`
- [ ] `G2GScanWorkflow` calls `CloneYakStateRepo(cfg.repoUrl)` as first step
- [ ] `G2GScanWorkflow` passes the path to `ScanG2GYaks(yakStatePath)`
- [ ] `G2GScanWorkflow` calls `CleanupYakStateRepo` in a `finally` block
- [ ] `G2GScanWorkflow` has a dedicated `proxyActivities` proxy with a timeout long enough for a git clone (e.g. `"3 minutes"`) for the clone/cleanup activities
- [ ] Existing `scanAct` proxy (30s timeout) used only for `ScanG2GYaks` and `StartYakWorkflow`

## Prerequisites
- add CloneYakStateRepo and CleanupYakStateRepo activities must be done
- split activities across shaver and watcher task queues must be done

# Files
- worker/src/workflow.ts (YakWorkflow + G2GScanWorkflow threading)
- worker/src/types.ts (add yakStatePath to YakWorkflowState)

# Notes
`CloneYakStateRepo` and `CleanupYakStateRepo` are not long-running but do
require network access and file I/O, so a 3-minute startToCloseTimeout is
appropriate for those proxied via `scanAct`-equivalent in G2GScanWorkflow.
